# 5. Current Flashlight System

## Working flashlight beam

The player has a functioning `SpotLight3D` flashlight beam attached to the camera.

The beam currently:

* Follows the player’s view.
* Points wherever the camera points.
* Produces shadows.
* Has a set range.
* Uses a controlled cone angle.
* Appears when the flashlight is equipped.
* Disappears when the flashlight is holstered.

The flashlight beam should remain attached to the camera unless the equipment system is intentionally redesigned.

A basic physical flashlight scene exists:

The flashlight model includes basic parts such as:

* Main body.
* Flashlight head.
* Lens.
* Switch.
* Dark metallic material.
* Emissive lens material.

The model is functional as a prototype but is not final-quality.

# 6. Current First-Person Equipment Rig

A camera-attached first-person equipment rig is currently working.

The current structure is approximately:

```text
Player
└── CameraPivot
    └── PlayerCamera
        ├── InteractionRay
        ├── Flashlight
        └── FirstPersonRig
            ├── HeldFlashlight
            ├── RightForearm
            └── RightHand
```

## FirstPersonRig behavior

`FirstPersonRig` is attached directly to `PlayerCamera`.

This means it:

* Remains inside the player’s view.
* Moves with the camera.
* Does not swing with the full-body walking animation.
* Can be hidden when no equipment is equipped.
* Can later contain different first-person equipment models.

## Temporary forearm

The current `RightForearm` is a temporary `MeshInstance3D` using a `CapsuleMesh`.

It is only being used to prove the first-person equipment position.

It is not a final character arm.

## Temporary hand

The current `RightHand` is a temporary `MeshInstance3D` using a `SphereMesh`.

It is only being used to represent the hand position around the flashlight.

It is not a final hand model.

## Current result

The following now work together:

* The fake forearm appears.
* The fake hand appears.
* The flashlight model appears.
* The flashlight beam appears.
* The rig follows the camera.
* The equipment no longer swings near the full-body character’s waist.

# 7. Current Script Connection

The current player script uses the entire `FirstPersonRig` as the visible held-flashlight object.

The expected reference is similar to:

```gdscript
@onready var held_flashlight: Node3D = (
	$CameraPivot/PlayerCamera/FirstPersonRig
)
```

The current equipment-visibility function should remain simple:

```gdscript
func update_equipment_visuals() -> void:
	var flashlight_equipped: bool = (
		current_equipment_id == "flashlight"
	)

	flashlight.visible = flashlight_equipped

	if held_flashlight != null:
		held_flashlight.visible = (
			flashlight_equipped
		)
```

This function controls:

* The camera flashlight beam.
* The full first-person flashlight rig.

Do not reintroduce references to `equipment_pose_modifier` into this function.

# 8. Abandoned Full-Body Arm Pose Attempt

A `SkeletonModifier3D` experiment was previously attempted.

The experimental script was:

```text
Scripts/equipment_pose_modifier.gd
```

The goal was to rotate the character’s:

* Right upper arm.
* Right forearm.
* Right hand.

The experiment did not work correctly because:

* The character skeleton’s bone axes did not match assumed rotations.
* The arm twisted.
* The arm moved behind the character.
* The arm disappeared from view.
* The walking animation continued affecting the pose.
* Absolute bone rotations damaged the arm’s normal orientation.

## Current rule

Do not reconnect the experimental modifier to the player without intentionally redesigning it.

The current camera-based first-person rig replaced that approach.

The modifier script may remain in the repository temporarily, but it should eventually be:

* Removed, or
* Rebuilt for a clearly defined future purpose.

# 16. Current Career and Shift Progress

The game currently tracks prototype career statistics such as:

* Current rank.
* Performance XP.
* Calls cleared.
* Shifts completed.
* Promotion requirements.
* Promotion eligibility.

## Shift completion

Going on duty begins a shift.

Clearing calls adds progress during the shift.

Ending the shift only counts as a completed shift when at least one call was cleared.

A shift summary explains whether the shift counted.

## Promotion status

Promotion eligibility currently depends on prototype requirements.

Eligibility does not automatically promote the officer.

The final promotion system will eventually need:

* Supervisor review.
* Time in service.
* Training.
* Department openings.
* Discipline history.
* Performance evaluations.
